# S3 storage and lifecycle reference

Use these read-only snippets for storage-class and retention investigations.
Substitute task-specific values for `$BUCKET`, `$PREFIX`, `$AWS_PROFILE`,
`$AWS_REGION`, and the other variables. Prefixes are literal key prefixes;
include a trailing `/` when targeting a folder-like subtree.

## Discover prefixes without listing every object

Use a delimiter to discover backup IDs or other logical groups cheaply.
Set `$PREFIX` to an empty string for the bucket root.

```bash
aws s3api list-objects-v2 \
  --bucket "$BUCKET" --prefix "$PREFIX" --delimiter / \
  --profile "$AWS_PROFILE" --region "$AWS_REGION" \
  --query 'CommonPrefixes[].Prefix' --output json
```

This automatically paginates. Root-level objects also exist: inspect
`Contents` if the question covers keys outside the returned subprefixes.
Prefixes have no storage class; their objects can use different classes.

## Inspect lifecycle policy

Use this to distinguish configured transitions/expiration from observed
object storage classes. A transition rule does not prove it has executed.

```bash
aws s3api get-bucket-lifecycle-configuration \
  --bucket "$BUCKET" \
  --profile "$AWS_PROFILE" --region "$AWS_REGION" --output json
```

Check enabled status, prefix/tag/size filters, transitions, expiration,
noncurrent-version actions, and incomplete multipart-upload cleanup.
Aborting incomplete uploads does not prune completed backup objects.
If changes are needed, find the owning IaC configuration before proposing
live edits.

## Start with bucket-wide storage totals

For a large bucket, use daily S3 metrics before launching a complete object
listing. Discover published storage-type dimensions first:

```bash
aws cloudwatch list-metrics \
  --namespace AWS/S3 --metric-name BucketSizeBytes \
  --dimensions "Name=BucketName,Value=$BUCKET" \
  --profile "$AWS_PROFILE" --region "$AWS_REGION" --output json
```

Then read the relevant series. `$STORAGE_TYPE` is a CloudWatch dimension
such as `StandardStorage` or `GlacierInstantRetrievalStorage`, not the object
API value `STANDARD` or `GLACIER_IR`. Use ISO timestamps for the time window.

```bash
aws cloudwatch get-metric-statistics \
  --namespace AWS/S3 --metric-name BucketSizeBytes \
  --dimensions "Name=BucketName,Value=$BUCKET" "Name=StorageType,Value=$STORAGE_TYPE" \
  --start-time "$START_TIME" --end-time "$END_TIME" \
  --period 86400 --statistics Average \
  --profile "$AWS_PROFILE" --region "$AWS_REGION" --output json
```

`BucketSizeBytes` and `NumberOfObjects` are daily metrics, so `--period 86400`
(a multiple of 60 and valid for any start age) with a window of several days
returns datapoints; `NumberOfObjects` publishes under its own `StorageType`
value, so take it from `list-metrics`. `--end-time` is exclusive.

Datapoints need not be sorted: select the newest timestamp explicitly and
report that date. These are delayed bucket-wide totals, not a live prefix
inventory. Published metric names alone do not prove current nonzero usage;
missing metrics or permission errors do not prove a class is empty. Do not
attribute a bucket total to a particular backup from its age alone.

## Sample actual object classes

Use a bounded page to confirm classes on individual objects before deciding
whether a full scan is necessary.

```bash
aws s3api list-objects-v2 \
  --bucket "$BUCKET" --prefix "$PREFIX" \
  --max-keys 1000 --no-paginate \
  --profile "$AWS_PROFILE" --region "$AWS_REGION" \
  --query '{truncated:IsTruncated,objects:Contents[].{Key:Key,Class:StorageClass,Size:Size}}' \
  --output json
```

`IsTruncated=true` means more keys remain. An empty non-Standard result on
one page is not proof that an entire prefix is Standard. Optional
`--start-after "$KEY"` changes the lexicographic starting point; it is not
random sampling or a date filter. Metadata files may have different classes
from large data objects, especially under lifecycle size filters.

## Obtain complete coverage when needed

Check for an existing inventory before scanning millions of keys:

```bash
aws s3api list-bucket-inventory-configurations \
  --bucket "$BUCKET" \
  --profile "$AWS_PROFILE" --region "$AWS_REGION" --output json
```

If a usable report includes storage class, check its report date, prefix
scope, and current/all-version coverage. Configuration alone is not a report.
Otherwise enumerate the required prefix with automatic pagination:

```bash
aws s3api list-objects-v2 \
  --bucket "$BUCKET" --prefix "$PREFIX" \
  --profile "$AWS_PROFILE" --region "$AWS_REGION" \
  --query 'Contents[].[StorageClass,Size]' --output text > "$OUTPUT_TSV"
```

Aggregate counts and bytes by class after successful completion. Repeat per
backup prefix when attribution matters, or retain keys in the projection.
Do not use `--no-paginate` or `--max-items` for a complete scan. These calls
read metadata, incur LIST requests, and can take time on large buckets.
Interrupted output is partial evidence. Listings during pruning/uploads
are not an atomic snapshot; record timing and account for concurrent changes.
`list-objects-v2` covers current objects, not noncurrent versions; inspect
versioning and use version listings/inventory when explaining total billing.

## Explain bytes missing from the current object listing

When billed storage exceeds visible object sizes, check noncurrent versions
and unfinished multipart uploads before assuming the metrics are wrong.

```bash
aws s3api get-bucket-versioning \
  --bucket "$BUCKET" \
  --profile "$AWS_PROFILE" --region "$AWS_REGION" --output json

aws s3api list-object-versions \
  --bucket "$BUCKET" --prefix "$PREFIX" \
  --profile "$AWS_PROFILE" --region "$AWS_REGION" \
  --query '{versions:Versions[].{Key:Key,Id:VersionId,Latest:IsLatest,Size:Size},deleteMarkers:DeleteMarkers[].{Key:Key,Id:VersionId}}' \
  --output json
```

An absent versioning status means versioning was never enabled; `Suspended`
can still leave older versions. Deleting a current key in a versioned bucket
can create a delete marker while retaining billable previous versions.
Keep the prefix narrow: version listings can also be large.

Discover unfinished uploads and their initiation dates:

```bash
aws s3api list-multipart-uploads \
  --bucket "$BUCKET" --prefix "$PREFIX" \
  --profile "$AWS_PROFILE" --region "$AWS_REGION" \
  --query 'Uploads[].{Key:Key,UploadId:UploadId,Initiated:Initiated}' \
  --output json
```

For an upload selected from that result, measure uploaded parts:

```bash
aws s3api list-parts \
  --bucket "$BUCKET" --key "$KEY" --upload-id "$UPLOAD_ID" \
  --profile "$AWS_PROFILE" --region "$AWS_REGION" \
  --query '{parts:length(Parts),bytes:sum(Parts[].Size)}' --output json
```

Leave CLI pagination enabled and use JSON for whole-result aggregates.
`--page-size` changes request size, while `--max-items` limits total returned
items. Sampling a few uploads establishes their size, not the total size of
all unfinished uploads. Compare actual upload keys against lifecycle
prefixes: a rule for a newer subtree does not cover older paths elsewhere.
These snippets inspect only; aborting uploads is a separate mutation.

Preserve errors when collecting reports: `AccessDenied`, an interrupted
listing, or failed JSON parsing must not become a zero-byte result. Keep
stdout and stderr separate and check exit status before aggregating files.
